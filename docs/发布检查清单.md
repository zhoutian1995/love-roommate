# Love Roommate 发布检查清单

这份清单用于判断“可以发布”，不是开发进度表。任何一项缺少直接证据，都必须继续处理，不能用测试通过、肉眼大致正常或旧 commit 的结果代替。

## 1. 产品契约

- 接受已授权、人物可分离的随机 1～8 人合照。
- 用户必须明确选择本人，也可以选择“本人不在照片”；不得根据中间位置或外观猜测。
- 本人在照片中时，本人必须是唯一站立的被膜拜者，不跪、不喊、无恶搞气泡；`recipientId` 必须是本人，`excludedIds` 必须严格只含本人，其余全员都是跪喊参与者。
- 本人不在照片中时，不得虚构被膜拜者；`recipientId` 必须为 `null`、`excludedIds` 必须为空、照片中全员都是跪喊参与者。
- 只有“照片仅一人且该人就是本人”时，跪喊才允许以 `no-eligible-participants` 明确跳过；其他人数与身份组合不允许全排除或 no-op。
- 跪喊人物慢慢移动后按配置顺序排队；单排放不下时居中多排，人物不重叠、不裁切、不越过工作区。
- 跪喊动作同步播放 `0 → 1 → 2`；不得写死五人、固定本人编号或固定人物顺序。

## 2. 图像与视觉

- 每个人物都有获批身份母版、完整动作、透明边缘和可验证生成记录。
- 每张动作图均以原分辨率实际查看；不能只依赖 JSON、统计或联系表缩略图。
- 不得残留绿色、洋红、白色或灰色色边，不得侵蚀头发、皮肤、衣服、手脚。
- 身份板、动作联系表和真实运行场景均完成第二次人工审核。
- `self-check-report.json` 为 `pass`，总分与每个人物分数均达到 Skill 规定阈值，人工项无 `pending`。

## 3. 行为与随机人数

- 自动测试逐一覆盖 1～8 人、本人在每个位置、本人不在照片，以及仅单人本人允许的明确跳过契约。
- 真实运行覆盖 normal、无本人鼠标屎人体蜈蚣、有本人持续拉且其余全员追吃、爸爸、爷爷、暂停。
- 八人窄屏验证居中多排、顺序稳定、无遮挡、无越界；五人只作为兼容性回归样例。
- 有本人时，本人逐渐移动到队形中心轴并始终站立，其余全员逐渐移动、排队、跪下并面向本人；无本人时全员排队跪喊且不存在站立接收者。

## 4. 性能与打包

- 同一候选版本完成 Windows 五窗口 packaged 回归和八窗口 packaged 最终审计。
- 两份报告逐秒证明全部人物窗口持续存在、可见且未销毁，并通过相同 CPU、帧时间、内存、启动和 Pause 阈值。
- Windows portable `.exe` 直接启动通过；托盘暂停/退出、拖拽、右键和透明像素点击穿透实际验证。
- Apple Silicon macOS 从同一 commit 构建并实际启动 arm64 `.app`，保留正确的框架相对符号链接。

## 5. 隐私与供应链

- Skill 仓库不含人物照片、生成图、用户输出、依赖缓存、私有路径或账号信息。
- 用户输出根目录完成隐私扫描；原图精确副本和符号链接均为零。
- 默认只使用官方 npm registry 与 Electron 官方发布源；第三方镜像必须显式授权。
- Electron 压缩包校验固定 SHA-256；Sharp fallback 版本与冻结锁文件一致。
- 根目录许可证和第三方声明完整，公开证据只使用虚构人物及脱敏 JSON。

## 6. GitHub 精确发布

- 所有预期修改已纳入一个可审计 commit，工作树干净。
- README 不再含发布标签或精确 SHA 占位符。
- GitHub Windows、macOS 和官方 Skill validator 三项终态全部成功。
- 从精确 commit 使用官方安装器 `--method download --ref <40 位 SHA>` 隔离安装。
- 隔离安装不含 `.git`，文件数、缺失项、额外项和逐文件 SHA-256 与 Git tree 完全一致。
- 从 exact ref 的干净 clone 和隔离安装分别复跑关键门禁；Live Skill 最终也从 exact ref 同步。

## 7. 可发布结论

只有 [发布证据模板](release-evidence-template.md) 的必填项全部有直接证据、独立复核没有未解决问题时，才能填写“可以发布”。
